# Pocket Drop v5: strict PqcLib

v5 is v4 with one library changed: `contracts-v4/src/PqcLib.sol`. It closes the hygiene item listed in
`docs/THREAT_MODEL.md` section 5 and `docs/AUDIT.md` section 5.1 ("PqcLib leaves the 4,627 / 2,592 byte sizes to the
precompile and the pinned key hash, and accepts a key-status offset above 0x80"). No other source file changed.

## What changed

| Check | v4 | v5 |
|---|---|---|
| Signature length in `PqcLib.verify` | left to the precompile | must be exactly 4,627 bytes, else `false` without calling the precompile |
| Public key length in `PqcLib.verify` | left to the precompile | must be exactly 2,592 bytes, else `false` without calling the precompile |
| Registered ML-DSA-87 key length in `checkKey` / `requireKey` | not checked (pinned hash only) | must be 2,592 bytes; new code `KeyCheck.BadKeyLength` / error `BadKeyLength()` |
| Key-status bytes offset | any word-aligned offset >= 0x80 | exactly 0x80 |
| Key-status return length | at least head + key | exactly 160 + key rounded up to 32 bytes (no trailing data) |

Every live Diana answer recorded so far has exactly this layout (`docs/PRECOMPILE_CONFORMANCE.md`, findings 1 and 3),
so v5 refuses nothing the chain actually returns. Consequence for users: a Pocket cannot be created for an owner whose
registered ML-DSA-87 key has the wrong length (v4 created it and it could never spend).

## Tests

| Suite | v4 (main before v5) | v5 |
|---|---|---|
| `forge test` (default, local) | 181 | 185 (4 new v5 tests: sizes before the precompile, fuzz over sizes, trailing key-status data, key length in `checkKey`; the gap-offset test now expects refusal) |
| `FOUNDRY_PROFILE=realcrypto forge test` (real ML-DSA-87 via ffi) | 22 | 22 (the truncated-key test now proves the Pocket cannot be created) |
| `FOUNDRY_PROFILE=ci forge test` (fuzz 10,000 runs, invariants 256 x 50) | 181 | 185 |
| `FOUNDRY_PROFILE=live forge test` (live Diana precompiles, eth_call) | 27 | 27 |

Three shared key-status vectors that v4 decoded (`offset-0xa0-with-gap`, `trailing-word`, `unaligned-extra-byte`) are
refused by v5; `KeyStatusVectors.t.sol` lists them by name.

## Gas (forge snapshot, same tests on both versions)

Over the 132 tests shared by both versions (PqcLib unit tests, vectors, fuzz and invariants left out because their
inputs changed): median +134 gas per test. Per signature check the size test costs about +182 gas
(`test_claim_to_plain_account_payto` 2,068,257 -> 2,068,439). Whole flows: the full relayed journey +433 gas
(4,464,296 -> 4,464,729), a pool with two claimers +498. Runtime size: PocketVault 17,200 -> 17,262 bytes,
PocketDrop 9,327 -> 9,389, DropPool 6,900 -> 6,989, PqGuardedCounter 2,958 -> 2,979; PocketFactory and PocketRouter
bytecode is unchanged (they are redeployed only because they point at the new contracts).

## Live smoke

`deployAndRelay` (lazy Pocket deploy), bound, claimed by a newcomer whose key registration the drip paid; one pool

registration, all success; 0.36 QOR in fees. Rows with hashes: `contracts-v4/LIVE_RESULTS.md`, section "v5 deploy and
live smoke"; raw record: `deployments/diana.json` -> `v5.smoke`.

## App migration

`prod` / `lab` in the API and the app now mean the v5 instances; the v4 instances stay reachable as `prodV4` / `labV4`
(old links `p…` / `l…`, Pockets made on v4, the recorded evidence). New v5 link ids start with `q` (prod) or `k` (lab).
The Pocket page offers a one-tap move when this key's v4 Pocket still holds QOR.
