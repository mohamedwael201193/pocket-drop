# Pocket Drop v5.2: finalize access control and explicit guarantees, redeployed

v5.2 is v5.1 with the guarantees behind the Stage 4 review items made explicit in the contracts. It was deployed on Diana
testnet on 26 Nov 2026 (about 03:52 Cairo time). New Pockets, drops and pools use v5.2. Links and Pockets made on v5.1, v5
and v4 stay on those contracts and keep working (claim, refund, cancel), so no old link breaks. Link prefixes: `s` / `n`
(v5.2 prod / lab), `r` / `m` (v5.1), `q` / `k` (v5), `p` / `l` (v4).

## What changed

| Item | v5.1 | v5.2 |
|---|---|---|
| Finalizing a recovery | `finalizeRecovery()` with no arguments; anyone could submit it after the delay (the target was fixed by the guardians) | `finalizeRecovery(authorizer, deadline, sig)` and `finalizeRecoveryUnanimous(authorizer, deadline, sig)`. The authorizer must be the owner, a guardian or the approved new owner (unanimous path: a guardian or the new owner, never the old owner) and signs `finalizeDigest(...)` with ML-DSA-87. The digest binds the action tag, chain id, vault, recovery nonce, new owner, new key hash, authorizer and deadline. Event `RecoveryFinalizeAuthorized`, error `NotAuthorized` |
| Reentrancy | every entry point of PocketDrop / DropPool locked, CEI | the vault has its own lock on spend, executeQueued, createDrop, confirmDrop, cancelDrop, createPool and closePool; `_pay` reverts `PayoutOutsideLock` unless the lock is held; vault events precede outgoing calls |
| Drip bounds | subtractive headroom | `spent > cap` checked first, then `drip > cap - spent`; the constructor rejects `dailyDripCap > type(uint128).max` |
| Targets and zero addresses | partial | drop and pool targets must be contracts; zero checks on the vault owner, factory implementation and router constructor (`ZeroAddress`) |
| Guardian loops | bounded by `MAX_GUARDIANS` | duplicate check by bitmap over the guardian index, every loop bounded |
| NatSpec | every contract, function, event and error | also every constructor parameter and public state variable (0 gaps, checked by a script) |

Signed message format: `qorechain-msg-v1|qorechain-diana|0x<finalizeDigest>`, the same envelope as the other Pocket
intents. Action tags: `keccak256("POCKET_FINALIZE_RECOVERY_V1")` and `keccak256("POCKET_FINALIZE_RECOVERY_UNANIMOUS_V1")`.
The app computes the digest locally, compares it with the on-chain `finalizeDigest` view, signs with the user's key and
then relays (`frontend/src/lib/actions.ts`, `finalizeAuthorization` and `finalizeRecovery`). On v5.1 and earlier Pockets the
app keeps calling the old no-argument functions.
